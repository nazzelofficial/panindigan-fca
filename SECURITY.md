Security Commitment

Security is a priority for Panindigan FCA.

We are committed to maintaining a secure software ecosystem by responding responsibly to security reports, improving our dependencies, and providing timely updates whenever possible.

We appreciate security researchers, contributors, and users who help identify and resolve security issues.


Supported Versions

Security updates are provided for actively maintained versions of Panindigan FCA.

VersionSupportedLatest release✅ SupportedPrevious major versions⚠️ Limited supportOlder versions❌ Not supported

Users are strongly encouraged to keep Panindigan FCA updated to the latest stable release.


Reporting Security Vulnerabilities

Responsible Disclosure

If you discover a security vulnerability in Panindigan FCA:

Please do not publicly disclose the issue.

Do not create a public GitHub issue, discussion, or pull request containing sensitive security details.

Instead, report the vulnerability privately so we can investigate and resolve it.


Security Report Contact

Send vulnerability reports to: security@panindigan.com

Subject line: Security Vulnerability Report - Panindigan FCA


Information to Include

A useful security report should include:

Vulnerability Details


Description of the vulnerability
Affected version(s)
Affected components
Security impact assessment


Reproduction Information


Steps to reproduce
Example code or proof of concept (if applicable)
Logs or screenshots when relevant


Additional Information


Suggested mitigation or fix
Your contact information for follow-up
Any relevant environment details


Providing detailed information helps us investigate faster.


Response Process

After receiving a security report, Panindigan will attempt to:

Initial Response — within 48 hours

We will acknowledge receipt of the report.

Investigation — within 7 days

We will provide an initial assessment and determine severity.

Resolution

The fix timeline depends on:


Severity of the vulnerability
Complexity of the issue
Required changes
Testing requirements



Severity Classification

Security issues may be classified as:

Critical

Examples:


Remote code execution
Authentication bypass
Severe data exposure
Complete system compromise


High

Examples:


Privilege escalation
Sensitive information disclosure
Significant security weaknesses


Medium

Examples:


Limited information exposure
Security configuration issues
Attack scenarios requiring specific conditions


Low

Examples:


Minor security improvements
Hardening recommendations



Security Updates and Disclosure

Once a vulnerability is fixed:


A security update may be released.
A security advisory may be published.
Credit may be given to the reporter (if desired).
Technical details may be disclosed responsibly.


Public disclosure timing may depend on:


Patch availability
User protection requirements
Severity of the vulnerability



Security Best Practices

Users and developers should:


Keep Panindigan FCA updated.
Use the latest supported runtime versions.
Keep dependencies updated.
Review dependency security advisories.
Never commit secrets or credentials.
Store API keys and tokens securely.
Use environment variables for sensitive configuration.
Use HTTPS for production communication.
Restrict access to production systems.
Follow secure deployment practices.



Dependency Security

Panindigan FCA may depend on third-party packages.

Security issues affecting dependencies will be evaluated and addressed when appropriate.

Users should regularly review:


Package updates
Security advisories
Dependency vulnerabilities



Security Advisories

Official security announcements may be published through:


GitHub Security Advisories
Official Panindigan announcements
Release notes


Users should monitor official channels for important security updates.


Bug Bounty and Researcher Recognition

Currently, Panindigan FCA does not operate a formal bug bounty program.

However, we appreciate responsible security research and may recognize contributors who help improve the security of the project.

Researchers may request acknowledgment in security announcements.
